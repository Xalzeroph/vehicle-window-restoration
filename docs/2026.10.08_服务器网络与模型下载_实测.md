# 2026.10.08 服务器网络与模型下载（实测）——更正"外网不通"的过期认知

> 起因：准备用 FoCo（CVPR 2025，多视觉基础模型协作）的思路做"该不该信"信号，需先确认能否在服务器上取基础模型。
> 结论：**能下**。此前记录的"服务器出站网络不通"是**片面**的（只对 `huggingface.co` 成立），今天实测更正。

---

## 2. 配方（写进运行守则）

```bash
# 下载阶段：走镜像
export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/home/zmy/data/cache/huggingface
python -c "from huggingface_hub import snapshot_download as d; print(d('repo/id'))"

# 运行阶段：缓存备齐后完全离线（零网络、零等待，避免 huggingface.co 超时重试）
export HF_HOME=/home/zmy/data/cache/huggingface
export HF_HUB_OFFLINE=1
```

**注意**：只设 `HF_HOME` 而**不设** `HF_ENDPOINT`/`HF_HUB_OFFLINE` 时，transformers 仍会去 `huggingface.co` 探测 `model.safetensors` → 报 `[Errno 101] Network is unreachable`（本轮踩过）。缓存齐了就用 `HF_HUB_OFFLINE=1`。

## 3. 已下载模型（本轮，合计约 1.1 GB）

| 模型 | 体积 | 角色 | 冒烟结果 |
|---|---|---|---|
| `openai/clip-vit-base-patch32` | 609 MB | **强模型**（FoCo 中的 CLIP：抓主要物体、对颜色/细微退化不敏感） | ✅ image features (1,50,768)；zero-shot logits 正常 |
| `facebook/dinov2-small` | 85 MB | 语义特征（轻量） | ✅ tokens (1,257,384) |
| `facebook/dinov2-base` | 346 MB | 语义特征（更强） | 已下（未冒烟） |
| `timm/resnet18.a1_in1k` | 47 MB | **弱/退化敏感模型**（FoCo 中的 ResNet 角色） | ✅ 权重加载 OK |
| `nvidia/segformer-b0-finetuned-ade-512-512` | 15 MB | **语义分割 150 类**（判断"洞区是不是语义对象"） | ✅ logits (1,150,128,128) |

torch hub 缓存另有：`vgg16` / `alexnet` / `fasterrcnn_resnet50_fpn` / `keypointrcnn_resnet50_fpn`（下游检测线可用）。

## 4. 解除了哪些阻塞

1. **FoCo 式探针**（强/弱异族模型的"鲁棒性差距" → 能否当"该不该信"信号）：现可直接开工；
2. **语义探针 S10**（洞区是否语义对象 → 失败形态是否不同）：SegFormer-B0 提供零样本语义分割；
3. **下游评测线**（三任务 × 固定下游模型 × Raw 基线）：检测/关键点权重已在本地缓存；
4. 后续如需 SAM：`github.com` 可达，可 `pip install git+https://github.com/facebookresearch/segment-anything.git`（未验证）。

## 5. 教训

- 一次运行时的 `huggingface.co` 失败（LOVO 训练时 pyiqa 拉 `dists` 权重）被记成了"**服务器出站网络不稳**"，并写进两份文档 → 导致今天一度放弃"下载基础模型"这条路。
- **更正**：不是"网络不通"，是"**该域名不通**"。凡涉及外部资源，应先做**端点级**连通性测试（本轮矩阵），再下结论。
