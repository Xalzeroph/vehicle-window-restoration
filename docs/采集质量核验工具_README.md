# 采集质量核验工具（拍完即验）

一行命令，输出"这批数据能不能用"的判决。

## 用法

```bash
# 直接给视频（自动抽帧）
python qa_capture.py VID_20261011_170340.mp4 --fps 5

# 或给已抽好的帧目录
python qa_capture.py frames5fps

# 指定报告路径
python qa_capture.py xxx.mp4 --out report.md
```

**依赖**：`opencv-python`（或 `opencv-python-headless`）+ `numpy`；视频输入另需 `ffmpeg` 在 PATH 里。
**内存**：流式处理 + 长边限 768 + 只保留中央裁剪，8 GB 笔记本可跑（实测峰值 <1 GB）。

## 输出

- 终端：判决表（✅/❌ + 每项说明）
- Markdown 报告：`<输入>_QA.md`，含判决表 + 数值明细 + 判据出处

## 八道门

| 门 | 指标 | 通过线 | 抓什么 |
|---|---|---|---|
| 1 | 反射段内 `\|g−1\|` 中位 | ≤0.02 | **AE/AWB 是否真锁死**（旧数据 0.1749） |
| 1 | 布段内 `\|g−1\|` 中位 | ≤0.02 | **布段是否自己还在动**（旧数据 0.04–0.21） |
| 2 | 反射段逐通道极差 | ≤0.03 | 是否需逐通道对齐（旧数据 max 0.308） |
| 3 | 跨段偏移逐帧变异系数 | ≤0.15 | 偏移是"场景级恒定"还是"逐帧乱跳"（后者=标签互相矛盾） |
| 4 | `corr(I, M)` | **<0.95** | **越低越好**——越低说明结构差异越大=越有东西可学；>0.95 才是坏事（只剩色调差） |
| 4 | 残差结构比 | ≥0.20 | 残差是**信号**还是噪声（旧数据 1.61 = 混了光度干扰） |
| 5 | 帧间位移中位 | ≤1.0 px | EIS/抖动是否破坏配对 |
| 5 | 反射强度 `r_obs` | ≥0.05 | 反射太弱学不到（旧数据 0.155，合成 0.155–0.634） |

## 判据出处

- 旧数据实测（对照基线）：`docs/2026.10.10_实拍数据诊断与VLM探针_结论.md`
- 采集方法决策（M−R vs 黑布）：`docs/采集方法决策卡_MR相减vs黑布_2026.10.10.md`
- 旧数据关键数：apr `|g−1|` 中位 **0.1749**、g 范围 0.953–1.393、逐通道极差 max **0.308**、
  8/11 场景 `corr(g, luma)` 0.97–1.00（AE 逐帧追赶）

**判决 7/8**：

`resid_raw 32.13 → 逐通道仿射后 16.37`（**全局对齐吸收一半，剩 16.37 且结构比 0.83 = 真反射**）。

## 已知限制

1. **需要"布段"存在且够长**（≥5% 帧数）。纯 M−R 采集（布挡背面）的分段逻辑不同，本工具不适用；
2. **布段切法**取了 `[布段起点+5, 布段终点−5]`，若揭布过渡很长会污染（首次实测就是这个问题）；
3. **单场景结论**：一次只能验一段视频。要确认采集协议稳定，需多场景各跑一次；
4. `r_obs` 含布的贡献（布的吸收），若要分离需 M−R。
