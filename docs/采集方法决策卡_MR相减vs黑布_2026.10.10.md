# 采集方法决策卡：M−R 相减 vs 黑布遮挡（2026-10-10）

> 缘起：实测确认现有"相机侧黑布"有两个缺陷——① AE/AWB 漂移（可修）；② **遮挡改变透射照明（不可修，相机侧遮挡的固有物理）**。
> 本文给出：**现场 3 分钟判定法** + **两套 SOP** + **对照表**。
> 关联：`docs/2026.9.22_自拍配对数据_拍摄规格.md`（协议 v2，本文是其增补，不替代）、`SIRR真实配对数据采集方法调研.md`（文献依据）。

---

## 0. 一句话

**"布挡玻璃背面"（M−R）能让 T 完全来自零遮挡帧 → 缺陷②结构性消除；但这要求够得到玻璃背面。够不到就只能退回黑布，缺陷②写进 limitations。**

---

## 1. 现场 3 分钟判定：够不够得到玻璃背面？

> ⚠️ **不要用宽高比反推**。本批全部为 1920×1080（16:9），但**设备型号未知**（原始 mp4 在用户本地，服务器上只有裁剪后的帧，无 EXIF），16:9 既可能是竖持 4:3 传感器裁切、也可能是设备原生视频模式。**只能靠几何判定。**

### 判定步骤（照做即可）

| # | 动作 | 判读 |
|---|---|---|
| 1 | **固定两个锚点**：站在拍摄位，取景框里选一处**透射侧**特征（玻璃后面的固定物，如插座/树/墙角）和一处**反射侧**特征（你自己的手） | — |
| 2 | **偏转测试**：保持姿态，横向平移相机约 10 cm | **反射侧特征（手影）位移明显大**、透射侧特征位移小 → **玻璃在两者之间** |
| 3 | **距离测试**：估一下你到玻璃的距离 d | **d < 20 cm** 且另一侧是封闭空间（车内）→ 倾向够不到 |
| 4 | **绕行测试（决定性）** | 走到玻璃另一侧，**同时保持能看到相机原位**。能 → **够得到**；不能（另一侧是车内/封闭/危险）→ **够不到** |
| 5 | **记进 meta**：`far_side_reachable: true/false`，`camera_to_glass_cm` | 后续所有场景一律按此执行 |

### 四条已从现有数据/文档确认的事实

| 事实 | 证据 |
|---|---|
| **反射源在相机侧且很近** | apr 帧底部有**拍摄者的手**；jun 有**拍摄者头肩剪影** |
| **相机贴着人**（离玻璃极近） | `README.md`：6 月多场景「**拍摄时衣服遮挡镜头**」，人工删了 13–171 帧/场景 |
| **拍摄贴近玻璃** | 人影占画面比例大（近场源）；照射边缘呈斜切（非正对） |
| **透射侧有真实场景** | jun 见带开关/插座的墙；may 见室内地砖 |

→ **强烈倾向"够不到"**：镜头能被衣服挡住说明相机紧贴身体，而身体又贴着玻璃；且另一侧若是车内则物理上不可达。**但仍须用 §1 步骤 4 实地确认**（若是在室外隔着窗户拍，另一侧是室内，就可能够得到）。

## 2. 方案 A：M−R 相减（够得到背面时用）★首选

**文献依据**：Lei et al. CVPR 2020 / CDR CVPRW 2022。原文明确支持"玻璃不可移"的约束：
> *"Since we do not need to remove the glass... we can utilize **immovable glasses in the real world**"*

### 2.1 原理

```
布挡玻璃【背面】  → 只有反射进镜头   → 拍 R
撤布（零遮挡）    → 反射 + 透射      → 拍 M
T = M − R        （RAW 线性域逐通道相减）
```

**T 完全来自零遮挡的 M → 透射照明原封不动 → 缺陷②消失。**

### 2.2 必须满足的前置条件（缺一即不可用）

| # | 条件 | 为什么 |
|---|---|---|
| 1 | **手机能出线性 RAW/DNG** | 相减必须在**线性域**做；JPEG 已经过 gamma/色调/tone mapping，相减无意义 |
| 2 | **能锁 ISO / 曝光时间 / 对焦 / 白平衡** | 两组帧若曝光不同，`T = M − R` 直接错 |
| 3 | **只有反射侧物体必须静止；透射侧可动** | 原文要求 |
| 4 | **三脚架 + 遥控/定时快门** | 两组帧必须逐像素对齐 |

**Android 路线**（可靠）：Camera2 API 的 DNG 输出 —— OpenCamera / Lightroom Mobile / ProShot / MotionCam，可锁 `CONTROL_AE_LOCK` / `CONTROL_AWB_LOCK` / 曝光时间 / ISO。
**⚠️ iPhone 存疑**：Flash-Split CVPR25 原文说部分 iPhone 不给 RAW；ProRAW 是**计算融合 DNG，不是传感器线性 RAW**。
→ **建议用 Android 机做主力**。

### 2.3 拍摄流程（改协议 v2 的第 2 步）

```
0. 三脚架固定相机；进专业模式/RAW 模式
1. 关掉：HDR / 夜景 / 美颜 / 场景识别 / EIS 电子防抖 / 变焦
2. 手动设置并锁定：ISO、曝光时间、白平衡(K)、对焦(MF)   ← 全程不改
3. 【新】走到玻璃背面，用哑光吸光布完全遮住玻璃背面（外扩 20–30 cm）
4. 拍 R 段：静止 ≥3 s（60fps ≥180 帧）
5. 【新】撤布，人退回原拍摄位（不要挡反射源），静止 ≥3 s
6. 拍 M 段：静止 ≥3 s
7. 同一场景内可【改变反射源内容】再拍 M₂ M₃ …（反射侧动、透射侧不动）
   → 一个场景得到 N 组 (R, M_i) → 数据量 ×N    ★这是 M−R 的一个额外优势
8. 全程不关灯、不变焦、不碰手机
```

### 2.4 后处理（线性域）

```python
# 伪代码：逐通道线性域相减
R_lin = dng_to_linear(R_frame)      # 保持线性，不做 gamma/tone
M_lin = dng_to_linear(M_frame)
T_lin = M_lin - R_lin
T_lin = np.clip(T_lin, 0, None)     # 负值置 0
T = same_isp(T_lin, metadata_of_M)  # 用 M 的 metadata 做同一套 ISP
```

### 2.5 质控门（不过 → 该场景重拍）

| # | 检查 | 通过线 | 依据 |
|---|---|---|---|
| 1 | **`mean(R)/mean(T) ∈ [0.1, 10]`** | 超出即丢弃 | Lei 2020 原文规则 |
| 2 | `T` 上有移动鬼影（透射侧动过） | 无 | 逐帧目检 |
| 3 | **曝光一致性**：R 段与 M 段的 `\|g−1\|` | **≤0.03** | 协议 v2 门 2 |
| 4 | 逐通道色偏：三段通道增益极差 | **≤0.03** | 新增（现有数据 max 0.308） |
| 5 | 几何对齐：相位相关峰值位移 | ≤2 px | 协议 v2 |
| 6 | 残留反射目检（R 段是否真的只有反射） | 目检通过 | RRW 点名 M−R 有残留 |

### 2.6 已知代价

- **需 RAW**（不能用 iPhone 计算摄影的 ProRAW）；
- **M−R 会残留少量反射**（RRW CVPR24 原文点名）→ 门 6 必须目检；
- **放大噪声**（相减是两次噪声相减）→ 原文建议长曝光 + 小 ISO。

## 3. 方案 B：黑布遮挡（够不到背面时的退路）

**只改一件事：把参数真正锁死。** 缺陷②无法解决，写进 limitations。

### 3.1 保留协议 v2，但补三条

| # | 补充 | 原因 |
|---|---|---|
| 1 | **从"长按锁定 AE/AF"升级为"专业模式手写 ISO/快门/WB"** | 「长按锁定」不锁白平衡、也不关计算摄影；实测现有数据 **8/11 场景 AE 在逐帧追赶** |
| 2 | **遮挡物改成"只遮反射源那一小块"，不要罩满全反射层** | 罩满=画面平均亮度掉最多（实测 luma 98→79），AE 必然补偿 |
| 3 | **GT 取在"布刚盖上"附近，而不是布段中部** | 减少布段内自身漂移（实测布段内抖动 0.04–0.21，比反射段大 2–4 倍） |

### 3.2 质控门 = 协议 v2 五门 + 新增一门

| # | 检查 | 通过线 |
|---|---|---|
| 1–5 | 沿用协议 v2（含曝光门 `g∈[0.97,1.03]`） | 见 v2 文档 |
| **6（新）** | **逐通道色偏**：通道增益极差 | **≤0.03**（现有数据 10/15 超标、max 0.308） |

## 4. 对照表

| | **A. M−R（挡背面）** | **B. 黑布（挡相机侧）** |
|---|---|---|
| 缺陷① AE/AWB | ✅ 可修（锁参数） | ✅ 可修（锁参数） |
| **缺陷② 改透射照明** | ✅ **结构性消除**（T 来自零遮挡帧） | ❌ **不可修** |
| 得到真正的 R 标签 | ✅ **有** | ❌ 无（只能靠 I−T 推） |
| 文献支持 | Lei CVPR20 / CDR CVPRW22 | RRW CVPR24 |
| 前置条件 | **够得到玻璃背面** + RAW + 锁参数 | 仅需锁参数 |
| 数据量 | **一场景 ×N**（改反射源内容，透射不动） | 一场景一组 |
| 已知代价 | 残留反射、放大噪声、需 RAW | 光度干扰大于反射本身（实测 std 34 vs 16） |
| 新颖性 | ⚠️ 【未找到】SIRR 领域有人这么做 | 已饱和 |

### 4.1 ⚠️ 贴膜车窗的额外几何问题（必须先想清楚）

**你们的反光发生在"玻璃 + 贴膜"的界面上。** 所以"哪一面是背面"取决于膜的贴法：

| 膜的贴法 | 反射界面 | 相机在车内时，**可够到的遮挡面** | 是否等于"背面"？ |
|---|---|---|---|
| 膜贴**车外侧**（常见） | 膜的外表面（空气-膜界面） | 车内 → 玻璃内表面 | ⚠️ **是"透射侧"**，不是反射界面另一侧 |
| 膜贴**车内侧** | 膜的内表面 | 车内 → **就是反射界面所在面** | ❌ 布会直接挡在反射面与相机之间 → **等价于黑布遮挡**（缺陷②照旧） |

**含义**：
- 若膜在外侧，你在车内只能挡到"透射侧的玻璃面"——那**不是 M−R 要挡的地方**；
- 真正要挡的是**反射界面的外侧**（车外）→ **相机必须也在车外**，或者能绕到车外操作。

**所以 M−R 的可行性还要加一条**：

> **相机与"反射界面的另一侧"必须在同一可操作空间内。**
> 对贴膜车窗：**相机在车外、且能绕到车外挡反射界面 → 可行**；
> **相机在车内（贴着玻璃拍）→ 无论膜贴哪侧都不可行。**

**三个方案，按可行性排序：**

| 方案 | 做法 | 代价 |
|---|---|---|
| **A1（首选）** | **相机移到车外**拍，布挡车外（= 反射界面外侧） | 需能到车外；场景真实性不变（还是同一块车窗玻璃） |
| **A2** | 若膜在内侧且相机必须在车内 → **不可行**，别试 | — |
| **A3** | 拆下玻璃单独拍（玻璃 + 膜脱离车）→ 变成实验室场景 | ⚠️ **会削弱"车窗"定位**，但你本来就没真车（AGENTS.md 记录），**可能可接受** |

**A3 值得认真考虑**：你们课题约束本来就是"只有车窗玻璃、没有真车"。**既然已经是"可控装置 + 单帧 + 合成/公开数据集"的定位，把玻璃取下来做可控采集与论文定位并不冲突**——反而能拿到文献里没人有的干净配对。
