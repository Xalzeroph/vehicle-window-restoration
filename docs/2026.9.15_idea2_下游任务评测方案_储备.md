## 1. 为什么值得存

1. **结构性地解决实拍 GT 难题**：任务指标吃的是**标注**（检测框/关键点/身份），不是逐像素 GT——
   实拍"揭膜 GT 与隔膜图对不齐"的问题直接消失（补光 GT 那种"对齐但不美观"的妥协也不再必要）。
2. **应用叙事强**：车窗后目标的可检出性/可识别性（安防盘查、停车场监控）比实验室物体的 PSNR 更打动审稿人。
3. **有本组一手证据打底**（`docs/2026.9.9_*`、记忆 `v1-oracle-prelude-0908`/`0909 扩展`）：
   - 9.8 预演：**乘性增强对检测器零信息增益**——乘性提亮保持相对对比 Δ 不变（人形 75→172、草地 91→188），
     梯度/NN 类检测器看到的结构不变；这是数学必然，不是调参可救。
   - 9.9 三批复跑：增强→检测**下降**（过曝）；RemoVal 白天响应=纹理误报主导。
   - ⇒ **任务指标的增益只能来自"去加性干扰（反射）"与"曝光/量化修复"，不能来自"变亮"**——
     这条判据天然把"提亮器"与"物理恢复"分开，是审稿人问"这不就是调亮度吗"的现成回答。

## 2. 实验设计：四臂 + 天花板

| 臂 | 处理 | 预期（据上述判据） |
|---|---|---|
| ① | 原始隔膜图（暗、带反射） | 基线 |
| ② | 纯提亮（gamma / CLAHE / Retinex） | ≈ ①（**复现自家负结果作对照**，不是浪费） |
| ③ | 仅去反射（RDNet zero-shot） | 涨——反射是加性干扰，去掉是真恢复信息 |
| ④ | **完整物理恢复（域适配分离器 + 除法出口）** | 最大涨幅（预期） |
| ⑤ | 天花板：**降窗/揭膜、同光同机位**再拍 | 物理上限 |

指标口径：任务指标（主）+ 感知指标（辅）；PSNR 不作主指标（对准 GT 不可用）。

## 3. 三个任务与协议（按优先级）

1. **人脸识别（故事最强）**
   - 协议：**登记**（不隔膜、正常光，每人 N 张）vs **探针**（隔膜、暗光）
   - 指标：人脸检出率 / rank-1 / 验证准确率（阈值化相似度）
   - 对齐无关、身份标签天然存在；可用自愿者（隐私合规）
2. **姿态检测**：OKS / PCK；无需身份，最易组织（几人摆姿势即可）
3. **YOLO 目标检测**：vehicle_ssd 资源现成；标注可从降窗 GT 上自动生成（现成模型跑一遍）

**难度扫描**：车窗高度控制膜覆盖率（全升 / 半升），必要时叠加不同膜或距离档。

## 4. 三个必须提前防的坑

1. **幻觉虚高**：生成式（扩散）恢复可能"把脸修得像登记照"→ 身份指标被作弊抬高。任务指标优先用
   **非生成式**恢复；若用扩散，必须加身份幻觉检验（如身份置换对照）。
2. **光子天花板**：拍之前先量隔膜图的曝光/噪声底——若光子不足（大面积欠曝到噪声底），
   任何算法都无解，先调拍摄参数（曝光时间拉到不过曝为止）再谈评测。
3. **过曝陷阱**：9.9 已踩过一次（增强→过曝→检测下降）；物理线目标是"恢复真实场景"而非"尽量亮"，
   天然规避，但评测流程要盯住输出亮度分布。
