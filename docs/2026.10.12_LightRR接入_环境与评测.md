## 2. 方法定位（读论文后）

| 项 | 值 |
|---|---|
| 架构 | U 形网络；**AFM**（Asymmetric Frequency Mamba）= Haar DWT → 只对 LL 低频做四方向 SSM → iDWT 把高频原样送回；**WDD/WSU**（小波下采样/上采样）替代插值；训练期用 VGG19 做**知识蒸馏**（推理期丢弃教师） |
| 规模 | **9.50 M params / 9.62 GFLOPs @224²** = RDNet 的 **3.01% 参数 / 5.22% FLOPs** |
| 相对 RDNet | 平均 PSNR 仅低 **0.26 dB**、SSIM 低 0.02 |
| 输出形式 | `forward` 返回 `(output_ts, encoder_feats)`；最细尺度带**全局跳连** `output_t_s[3](x) + inp_img`（`lightrr.py:586`）——残差式输出 |
| 评测协议 | 输入 `blended` / 真值 `transmission_layer`；`--if_align` 把两边 resize 到 `h//32*32, w//32*32`；指标 = skimage PSNR/SSIM，`data_range=255`，**逐通道算再取均值**；输出 clip 到 [0,1] 再 ×255 |

### 2.1 与"车窗课题"的关系（**定位问题，须明确**）

**LightRR 是通用单图去反射（SIRR）模型，不是"玻璃反光 + 夜间低光"联合任务模型。**
- 它不建模低光退化，也不建模贴膜/车窗几何；
- 对本课题的价值：① **通用 SIRR 轻量 SOTA 基线**；② 以 9.5 M 体量给出"通用方法在车窗域能到哪"的参照；③ 其**小波 + 状态空间**设计可作本课题轻量化路线的对照。
- **不要**把它当作本课题任务的直接竞争对手或解决方案。

### 3.2 一条更省事的备选路（**已验证可行，供无编译条件时用**）

本仓 `ExpoMamba/models/selective_scan_triton.py` 是**同签名的 Triton 实现**，
其文件头自述："本仓库 vmamba.py 依赖 mamba_ssm 编译算子，而目标环境无法编译安装
mamba_ssm（无 nvcc）。本模块提供同签名替代。"

其期望的调用布局与 LightRR 的调用**逐项一致**：

| | ExpoMamba 注释声明 | LightRR 实际传入 |
|---|---|---|
| `u` | `(B, K*D, L)` | `xs.view(B,K,-1,L)` → `(B, K*D, L)` ✅ |
| `A` | `(K*D, N)` 已取负 | `-torch.exp(A_logs)` ✅ |
| `B` / `C` | `(B, K, N, L)` | `(B, K, N, L)` ✅ |
| `D` / `delta_bias` | `(K*D,)` | `(K*D,)` ✅ |
| `z` / `return_last_state` | 恒 `None` / `False` | 传 `z=None, return_last_state=False` ✅ |

**结论**：本课题已有现成的 Triton 替代品，**mamba 编译不是必经之路**。
本次因为编译最终成功（CUDA 版是官方路径），正式数字仍用 CUDA 版。

## 5. ⚠️ 发现 LightRR 代码的一个真实 Bug（**会影响我们所有数据**）

### 5.1 现象

`AFM_LowFrequencySSM.forward` 结尾：

```python
y = self.idwt(torch.cat([y_ll, x_lh, x_hl, x_hh], dim=1))
yb, yc, yh, yw = y.shape
assert yb == B; assert yc == C2; assert yh == H; assert yw == W   # ← 这里炸
```

而 `IDWT_2D` 在**任一维为奇数**时会**静默丢掉一行/一列**：

```
实测：idwt((1,256,48,67)) -> (1,256,96,134)      # 67 -> 134，丢了一列
      ASSERT expects  H=96 W=135
```

### 5.2 尺寸鲁棒性实测（`scripts/lightrr_infer.py` 的 sweep）

| 输入尺寸 | 结果 |
|---|---|
| 224×224 / 256×256 / 288×288 / 240×320 | ✅ OK |
| **384×540 / 540×384 / 400×540** | ❌ AssertionError |
| 225×224 / 224×225 / 223×223 / 226×226 / 100×100 | ❌ AssertionError |
| 1080×1920 | ❌ OOM（10 GB 卡不够，与尺寸合法性无关） |

**规律**：H、W **必须都是 32 的倍数**（逐级下采样后每级都需偶数）。

### 5.3 为什么这件事对我们特别重要

我们的数据**几乎全部违反这个约束**：

| 数据 | 尺寸 | 是否 32 的倍数 |
|---|---|---|
| real20 | 1114×717 / 1126×740 / 678×517 … | ❌ |
| SIR2 | 540×400 | ❌ |
| 本课题自采（apr/may/jun） | 955×934 / 1427×859 / 1018×671 … | ❌ |

LightRR 自己的评测用 `--if_align` 把图 **resize 到 `h//32*32, w//32*32`** 规避
——**这等于承认了该约束，但用"改尺寸"绕过**。这会让它的输入与
RDNet 等基线**不一致**（别人不裁），横向比较就不公平。

### 5.4 我们的处理（**已实现并验证**）

`scripts/lightrr_infer.py` 提供 `LightRRInfer`：**pad 到 32 的倍数 → 推理 → 裁回原尺寸**。
理由：不改原图内容、输出尺寸恒等于输入（可与 RDNet 逐像素对齐）、224 倍数时零开销。

**12 尺寸实测 11 通过**（唯一失败是 1080×1920 OOM）：

```
540x400 (+4,+16) OK     717x1114 (+19,+6) OK    740x1126 (+28,+26) OK
517x678 (+27,+26) OK    255x257 (+1,+31) OK     1x33 (+31,+31) OK
```

### 5.5 另一个必须知道的限制：全局注意力 → O((H·W)²)

`CrossChannelAtt` 在 `h*w` 上做全局注意力，矩阵是 `(b, heads, hw, hw)`。
SIR2 的 540×400 下约 **0.55 GB**（可跑）；real20 的原生 1114×717 需要
**约 25 GB**——这正是论文要给 real20 单独设 `real20_420` 的原因。
→ **本课题的大尺寸自采数据（如 1920×1080）必须先降采样到 ~420–540 长边**，
否则不是精度问题而是直接 OOM。
